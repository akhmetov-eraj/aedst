# aedst web

The web client for the `aedst` monorepo: a Next.js app that reaches
`apps/server`'s ConnectRPC API **only through its own server** (see
[Architecture](../../docs/content/architecture-web.md#auth-data-and-security-model)).
The session lives in httpOnly cookies — page JavaScript never sees a token —
and the browser calls a same-origin `/api/rpc` proxy that attaches the bearer
token and refreshes it transparently.

## Tech stack

- **Next.js 16** (App Router, Turbopack) + **React 19**
- **ConnectRPC** via [Connect-ES](https://connectrpc.com/docs/web/getting-started) —
  `@connectrpc/connect` / `@connectrpc/connect-web` / `@connectrpc/connect-query`,
  with TypeScript client stubs generated by `buf` + `@bufbuild/protoc-gen-es`
  straight from `apps/server/api/proto`
- **TanStack Query** for client-side caching around Connect calls
- **next-intl** for i18n across five locales: `ar`, `en`, `ru`, `tj`, `uz`
- **Sentry** (`@sentry/nextjs`) for error tracking + session replay — client/server/edge
  configs in [`src/app/config/sentry`](src/app/config/sentry), wired through
  [`src/instrumentation.ts`](src/instrumentation.ts) /
  [`src/instrumentation-client.ts`](src/instrumentation-client.ts) and every
  route segment's `error.tsx` + the root `global-error.tsx`
- **Biome** for linting and formatting
- **Vitest** + Testing Library + MSW for unit/integration tests (coverage thresholds enforced)
- **Playwright** (Chromium, Firefox, WebKit, Pixel 7, iPhone 14) + axe for end-to-end, accessibility and responsive tests, against an in-memory mock of the API
- **Lighthouse CI** and a gzip **bundle budget** for performance

## Getting started

### Prerequisites

- Node.js 24+
- pnpm (see `pnpm-workspace.yaml` / the lockfile for the version)
- A running `apps/server` instance if you want real API responses (see
  `apps/server/README.md`) — by default it listens on `:8080`

### Install

```bash
pnpm install
```

### Configure environment variables

Copy `.env.example` to `.env.local` and adjust as needed:

```bash
cp .env.example .env.local
```

See [`.env.example`](.env.example) for the full, commented list (public vars
the browser sees vs. server-only ones — see
[`src/shared/env`](src/shared/env)); the ones worth calling out:

| Variable | Description | Default |
| --- | --- | --- |
| `NEXT_PUBLIC_SITE_URL` | This app's public origin — drives metadata/SEO | `http://localhost:3000` |
| `API_BASE_URL` | Server-only address of `apps/server`'s ConnectRPC API (the browser never uses it) | `http://localhost:8080` |
| `AUTH_COOKIE_NAME` | Base name of the httpOnly session cookies | `aedst_session` |
| `NEXT_PUBLIC_SENTRY_DSN` | Sentry DSN (optional) | — |
| `NEXT_PUBLIC_BETTER_UPTIME_HEARTBEAT_URL` | Better Uptime heartbeat URL (optional) | — |
| `SENTRY_AUTH_TOKEN` | Server-only; enables Sentry source-map upload during `next build` (optional) | — |

### Generate the ConnectRPC client

The TypeScript client stubs under `src/shared/api/connect/generated` are
generated (not committed — see `.gitignore`) from `apps/server/api/proto` and
must be regenerated after checkout and whenever those `.proto` files change:

```bash
pnpm connect:generate
```

This runs `buf generate` (config in `buf.gen.yaml`) against
`apps/server/api/proto`'s `auth`, `users`, and `profile` services (the
`events.proto` files are NATS event schemas, not RPCs, and are intentionally
excluded).

### Run the dev server

```bash
pnpm dev
```

Open [http://localhost:3000](http://localhost:3000).

## Testing

### Unit tests (Vitest)

```bash
pnpm test          # run once
pnpm test:watch    # watch mode
pnpm test:coverage # with coverage
pnpm test:ui       # Vitest UI
```

### End-to-end tests (Playwright)

```bash
pnpm test:e2e:prod    # builds the app, then runs all browsers against it
npx playwright test --project=mobile-safari   # one project (see playwright.config.ts)
pnpm test:e2e:headed  # headed mode against the dev server
pnpm test:e2e:debug   # Playwright inspector
pnpm test:e2e:report  # view the last HTML report
```

Playwright starts the app and `e2e/mock-api` (an in-memory stand-in for
`apps/server` speaking the Connect JSON protocol) itself, so login, token
refresh, dashboard, filters, pagination and CRUD run with no database or Go
service. Install engines once with `npx playwright install`.

### Performance budgets

```bash
pnpm build && pnpm check:bundle   # gzip JS/CSS ceilings (bundle-budget.json)
pnpm lighthouse                   # Lighthouse CI: scores, LCP/CLS/TBT, script weight (lighthouserc.json)
```

### Supported browsers

Chrome/Edge ≥ 111, Firefox ≥ 128, Safari/iOS ≥ 16.4 (`browserslist` in
`package.json`) — the baseline of Tailwind CSS 4.

### Lint / format / typecheck

```bash
pnpm lint             # biome check
pnpm lint:fix         # biome check --write
pnpm format           # biome format --write
pnpm typecheck        # tsc --noEmit
```

Both run automatically as a Lefthook pre-commit hook, scoped to only fire
when `apps/web/**` files are staged — see [`../../lefthook.yml`](../../lefthook.yml).
`lefthook install` (run once per clone, from the repo root, after
installing the `lefthook` CLI) wires it up; without that, nothing changes —
these still run individually as above, and CI still runs them regardless.

## Project structure

```
src/
  app/                # Next.js App Router: routes, providers, i18n/sentry/seo config
    sitemap.ts        # /sitemap.xml — one entry per locale, hreflang alternates
    robots.ts         # /robots.txt
    manifest.ts       # /manifest.webmanifest
    global-error.tsx  # catches errors the root layout itself throws
  modules/            # feature modules (ui/ + i18n/ + lib/, one dir per business feature)
  shared/             # cross-feature infrastructure — see src/shared/README.md
    ui/               # shared UI primitives (shadcn-based) — the web "design system"
    api/connect/      # Connect-ES transport/client setup + generated stubs — the web "network" layer
    date/             # date-fns formatting helpers, locale-aware
    env/              # client.ts (NEXT_PUBLIC_* only) / server.ts (`server-only`-guarded secrets)
    lib/              # remaining cross-cutting utilities: auth/ (session state, token storage,
                       # auth interceptor), hooks/, utils/, query-client.ts
```

Feature modules only ever import from `shared/**` (or from `app/**`, which
composes them) — never from another module directly. This is enforced by
`pnpm check:feature-boundaries` (see [`scripts/check-feature-boundaries.sh`](scripts/check-feature-boundaries.sh)),
the same rule Android/Apple/Desktop enforce between their own feature
modules.

See `AGENTS.md` for Next.js-version-specific conventions used in this app.

## Cross-platform module vocabulary

AEDST's Android, Apple, Desktop and Web clients all converge on the same
two-layer shape: a `core`/`shared` layer of non-feature-specific
infrastructure, organized by concern, plus one `feature` directory per
business feature that may only reach other features through that shared
layer. Web keeps its own technology (Next.js/React/TypeScript) — this is a
naming/organization convention, not a platform behavior change. See
[`src/shared/README.md`](src/shared/README.md) for the detailed mapping from
`src/shared/*`'s subfolders to each native platform's `core/*` module names,
and for why some equivalences are documented rather than physically renamed
(import-path risk vs. benefit).
