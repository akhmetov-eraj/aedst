# Decisions: Server

Part of the [decisions index](/decisions). Status and verification legends are defined there.


| Decision | Status | Rationale | Revisit when |
|---|---|---|---|
| Valkey (go-redis client, `AEDST_VALKEY_*`) replaces Redis; **cache and `redis_rate` only, never correctness** | Accepted | Open licence; anything that must be correct lives in Postgres ([ADR-0010](/decisions/0010-caching-and-data-partitioning)) | Valkey client ecosystem diverges from go-redis |
| RedSync removed; Postgres advisory locks (`internal/platform/lock`) | Accepted | Redlock-style locks are not safe for correctness; Postgres is already the source of truth | A lock must span systems other than Postgres |
| NATS JetStream removed; integration events are **River jobs inserted with `InsertTx` in the producer's transaction** (one job per subscribed consumer; `internal/platform/events` `Publisher` + `Registry`, consumers are River workers, handlers idempotent, no inbox table); River is the single async mechanism (events and deferred jobs). **NATS JetStream/Kafka only when a consumer becomes a separate service; `events.Publisher` is the seam. Never publish from request handlers outside a transaction.** | Accepted (owner decision, 2026-10) | [ADR-0014](/decisions/0014-river-insert-tx-as-outbox) (supersedes [ADR-0011](/decisions/0011-outbox-relay-and-in-process-bus), which superseded [ADR-0004](/decisions/0004-nats-jetstream)); one mechanism to operate, no relay, bus or inbox to maintain | A consumer becomes its own service (add a broker adapter behind `Publisher`), or measured `river_job` churn from deliveries threatens the primary workload ([scaling](/server/scaling)) |
| Router: replaced by net/http ServeMux (owner decision); realclientip-go for client IP; rs/cors | Replaced | Fewer dependencies; Chi was only needed for probes/metrics/webhooks, RPC mounts via `mux.Handle`. Client IP uses a trusted-hop strategy, never blind `X-Forwarded-For`/`X-Real-IP` | Revisit if routing needs outgrow ServeMux patterns |
| Goose kept; one version table per module (`goose_<module>`); squawk migration lint (`task lint:migrations`); `sqlc vet` | Kept | Atlas is paid; per-module tables keep the modular monolith splittable | Atlas (or an alternative) becomes free and clearly better |
| Server is an OIDC resource server (jwx v4 + `jwkfetch`, `AEDST_OIDC_*`, asymmetric-only allow-list). ZITADEL default (AGPL-3.0 core since v3: used unmodified as a separate service, no obligations on app code), Keycloak (Apache-2.0) the alternative for projects that ban AGPL, Ory not recommended. New projects set `AEDST_AUTH_FIRST_PARTY_ENABLED=false`; first-party auth (argon2id, refresh rotation with CAS and reuse detection) is a time-boxed migration path, off by default, with a mandatory `AEDST_AUTH_FIRST_PARTY_SUNSET` and a Sunset runbook (`docs/content/server/runbook.md`); no self-built MFA, recovery or social login | Accepted | `apps/server/docs/adr/0017-identity-provider.md` (in-repo path, not a docs-site page) | IdP licence changes; a project needs something no IdP offers |
| ZITADEL operations contract: JWT access tokens only (an opaque token yields `auth.ErrOpaqueToken` plus a rate-limited warn log, not a silent 401); audience = project id via scope `urn:zitadel:iam:org:project:id:<projectId>:aud`; roles from `urn:zitadel:iam:org:project:roles` with project role assertion on, optionally restricted to one organisation by `AEDST_OIDC_ROLES_ORG`; service-to-service uses ZITADEL machine users (client credentials or JWT profile). ZITADEL shares the CloudNativePG cluster only with a **separate database and role**, connects directly (never through the transaction-mode PgBouncer Pooler). Optional official Helm chart for the IdP. Legacy password hashes can be imported (`deployments/zitadel/import-users.sh`, user ids preserved) | Accepted. `bootstrap.sh`, `import-users.sh` (argon2id + bcrypt hashes), roles/audience/`end_session`/refresh behaviour and the server `OIDCVerifier` verified on 2026-10-08 against ZITADEL v4.19.4 (release binary, no Docker; needs `ZITADEL_SYSTEMDEFAULTS_PASSWORDHASHER_VERIFIERS=argon2,bcrypt`; machine users carry roles only in `urn:zitadel:iam:org:project:<projectId>:roles`, so `AEDST_OIDC_ROLES_CLAIM` uses that claim). The compose `idp` profile, Helm chart and Login UI v2 are UNVERIFIED (Docker engine would not start) | Keeps identity data and load apart from app data, avoids transaction-pooling breakage, and lets the first-party path be deleted early ([ADR-0001](../../../apps/server/docs/adr/0017-identity-provider.md)) | ZITADEL gets its own cluster, or the IdP changes |
| Push: one canonical document, [Push notifications](/server/push), for device registration (Web Push subscription shape, FCM/APNs tokens), the payload contract and VAPID rotation; other docs link to it. The server holds a single VAPID key: a dual-key overlap is **not implemented** (rotation is a planned cutover with client resubscription) | Accepted | One place to keep current; the single-key limit is stated, not hidden | Dual-key rotation is implemented (per-device `vapid_key_id`) |
| Observability: OpenTelemetry OTLP via standard `OTEL_*` to any backend (Grafana Cloud / SigNoz / HyperDX); local compose profile `observability` = single `grafana/otel-lgtm`; Prometheus `/metrics` optional and off by default; otelhttp + otelconnect; no self-hosted Tempo/Loki/Pyroscope by default | Accepted | Vendor-neutral, one container locally, no stateful telemetry stack to operate | A team decides to self-host a backend (then document it) |

| Standard gRPC health (`grpc.health.v1`, driven by `/readyz`'s `Readiness`) is always served; gRPC reflection only when `AEDST_GRPC_REFLECTION_ENABLED=true` (`connectrpc.com/grpchealth`, `connectrpc.com/grpcreflect`) | Accepted | The server already speaks gRPC; balancers and `grpcurl` expect these; reflection publishes the API surface, so it is opt-in | — |
| Role policy is configuration, validated at startup: `AEDST_ROLE_POLICY` (`/pkg.Svc/Method=role\|role,…`) is parsed by `httpserver.ParseRolePolicy` and checked against the procedures derived from the protobuf descriptors; an unknown or public procedure, or a procedure with no role, **fails startup** | Accepted | A typo in an allow-list must not leave the real RPC silently open, and adding an admin RPC must not require touching wiring code | An RPC needs per-resource (not per-role) authorization: that belongs in the module's application layer |
| Alerts (`PrometheusRule`), a Grafana dashboard and a per-alert runbook ship in the Helm chart; alerts are written in native Prometheus format and reference only the server's own OTel metrics | Accepted | An SLO nobody is paged for is a wish; [runbook](/server/runbook) | Thresholds are re-derived from a production-shaped load test ([scaling.md](/server/scaling#load-testing)) |

One state backend (S3-compatible remote with locking), `.terraform.lock.hcl` committed, providers pinned with `~>` constraints, toolchain pinned in `mise.toml`. No `.tf` is written until the cloud target is chosen | Accepted; no infra code yet | Same open-license stance as Valkey; OpenTofu reads existing Terraform HCL/providers, so the choice is cheap to keep; two IaC tools means two states and two lock policies | The cloud target is chosen (write the modules), or OpenTofu stops being maintained |
