# Decisions: Cross-cutting

Part of the [decisions index](/decisions). Status and verification legends are defined there.


| Decision | Status | Rationale | Revisit when |
|---|---|---|---|
| Latest stable versions, verified against the registry, never invented ([library-first](/library-first#version-policy)) | Accepted | Hallucinated versions break builds and hide vulnerabilities | Never; it is a process rule |
| "Approved before first use" is machine-enforced (knip allowlist on Web; `go mod tidy` + golangci-lint `depguard` on Server); allowlist changes require a docs update | Accepted | Convention alone let unused dependencies accumulate | A platform gains a better native enforcement mechanism |
| mise pins toolchains (`mise.toml`), root `Taskfile.yml` is the single entry point, design tokens come from `packages/design-tokens` (Style Dictionary), generated files are never hand-edited | Accepted | One place per concern; removes version drift and per-platform token copies | Tooling proves insufficient for a platform (record the gap first) |
| Modular monolith, module boundaries, ConnectRPC, PostgreSQL | Accepted | [ADR-0001](/decisions/0001-modular-monolith), [0002](/decisions/0002-connectrpc), [0003](/decisions/0003-postgresql), [0006](/decisions/0006-module-boundaries) | See each ADR |
| AEDST is an empty template: it ships only global modules (auth, tasks as the worked example, search, notifications, media, admin); product-specific domains are added by each product, never by the template | Accepted | A template that guesses a product's domain is a product, not a template ([modules.md](/server/modules)) | — |
| One telemetry split on every client: **Sentry** = errors, crashes, performance, tracing (trace propagation to the API only); **PostHog** = product analytics + feature flags, opt-in by consent and off when its key is empty; the server stays OpenTelemetry-only | Accepted | One primary tool per responsibility across platforms; traces join client and server | A product needs a single vendor for both |
| Push channels: Web Push (VAPID) on web, FCM on Android (Firebase Admin Go messaging client), APNs on Apple (apns2, token auth), tray + polling on Desktop; one payload contract (`kind`, `title`, `body`, `link`, `notification_id`); server providers are libraries, see "Push providers via libraries" | Accepted | Each platform's native channel; no Firebase on web/iOS (Apple devices register raw APNs tokens, browsers a Push API subscription) | A platform loses its native channel |
| Supply-chain pinning: every third-party GitHub Action is pinned by full commit SHA with a `# vX.Y.Z` comment; Renovate extends `config:best-practices` (digest pins for Actions and Docker); `gofumpt`, `govulncheck` and `goose` are pinned in `mise.toml`; CI renders the chart with Helm 4 (tested with 4.3.0, UNVERIFIED on 3.x) | Accepted | Mutable tags let an upstream change run in CI unreviewed; one pin location per tool avoids drift between workflows and local runs | A pinned action or the Helm major becomes unmaintained, or the `go:` mise backend proves unreliable in CI |
| `scripts/update-deps.sh` (`task deps:update` / `deps:check`) bumps every platform with its native tooling on demand; Renovate stays the continuous path | Accepted | One command for "latest stable everywhere" without hand-rolled resolution | — |
| The server is **not** a design-token target. It renders no UI: no email templates, no HTML, no Open Graph images, no brand colors (checked 2026-10-08: no hex/rgb color literal in `apps/server` outside generated code; the only templates are Helm manifests). Push payloads carry text only | Accepted | A Go token output with no consumer would be dead generated code and an extra build target to maintain | The server starts rendering branded output (transactional email, server-rendered OG images, PDF/exports); then add an optional Go target to `packages/design-tokens/build.mjs` and update `scripts/check-color-literals.mjs` rules for `apps/server` |
| Repo-wide policy nets run on every PR (`policies-ci.yml`, `task check`): file size (green up to 300, yellow 301-400, orange 401-500, red over 500 fails; `scripts/file-size.config`), color literals banned outside generated token files (`scripts/check-color-literals.mjs`, allowlist with reasons), i18n key/placeholder parity for en/ru/tg/uz/ar (`scripts/check-i18n-parity.mjs`, canonical Tajik code `tg`), one boundaries entry point for all five platforms (`scripts/check-boundaries.sh`). Apps may add stricter checks; these are the floor | Accepted | Per-app checks drift apart; a single net keeps the five platforms to the same standard and makes gaps visible | A rule proves to produce more false positives than defects; adjust the config/allowlist, not the policy silently |
| `task template:new` (`scripts/template-new.mjs`, declarative `scripts/template-profiles.json`) derives a product repo with profile `core` (server + web), `mobile` (+ android, apple) or `full`, and renames only external identifiers (display name, Android applicationId, Apple bundle prefix, Velopack/Flatpak id, Helm chart/image names, domains, cookie name). The proto packages `aedst.*`, the Go import path, `Aedst*` types, the QML URI and the `AEDST_` environment prefix are a **permanent internal codename** and are never renamed | Accepted (owner decision on the `AEDST_` prefix recorded in the task report) | Renaming wire-level and import-level identifiers touches generated code on five platforms, breaks wire compatibility and gains nothing a user sees | A rename becomes a customer requirement (white-label SDK, public proto package); then add a verified rename step to the tool for that identifier only |
| The `flagged` set is identical on every client: **only `admin` is flagged** (hidden until the server enables it); every other feature is a built-in that is shown unless the server switches it off. Web declares it in the module manifest (`flagged: true`), Android in `CapabilitiesModule`, Apple in `AppFeature.flagged`, Desktop in `desktopClientBuild`; `features.yaml` records it per feature and `task check:features` compares it with those declarations | Accepted | The server advertises every registered module as enabled by default and an operator gates one through `AEDST_FEATURES`, so the server policy has no per-client exceptions; the admin surface is the one feature that must stay hidden when nothing was ever negotiated (first launch offline), and Android, Apple and the shared capabilities fixture already did so. Web and Desktop used to show it as a built-in | A second feature needs default-off behaviour (add it to the set on every client in one change), or admin must work before the first successful capabilities fetch |
| One error vocabulary on every client: `unauthenticated, forbidden, notFound, invalidInput, conflict, rateLimited, unavailable, offline, timeout, cancelled, upgradeRequired, storage, unknown`, with `retryable` and `reportable` flags, the Connect code to kind table and the outbox verdict per kind in `docs/contract/behavior/error-kinds.json`. Each client names its enum cases after it and replays the file; `cancelled` never shows an alert; only `unknown` and `storage` are reportable (server faults are captured server-side) | Accepted | The four clients had drifted: Connect `canceled` was a network error on Apple, `failed_precondition` was a conflict on Web but a validation error on Android and Apple, and the retry and Sentry rules differed per platform | A new kind is needed (add it to the file and to all four enums in one change), or Android and Web adopt the outbox `blocked` verdict that Desktop already has |
| A feature has the same id on every platform (`features.yaml` key, Web manifest `id`, Desktop plugin id, capability id) and the same shape: layers, five-locale catalog, tests, one navigation entry, declared `flagged`, `outbox` types, i18n `namespace` and `routes`. `scripts/check-features.mjs` enforces it; a deviation is declared under `exceptions` in `features.yaml` with a reason | Accepted | A new feature had to be copied by hand from the reference module with nothing to catch a forgotten layer, locale or navigation entry | A platform changes its layout convention (update the check and the exception list in the same change) |
