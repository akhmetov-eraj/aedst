| Sign-out forgets user data held outside the database: media disk cache, decoded images and video thumbnails are cleared in `onSignedOut()`; refresh/access tokens (`Session`, `UnaryCall::sentToken`) are `SecretString`s and the body of a `Public` RPC (login, refresh) is wiped after the call; sign-in carries a random `nonce` that the ID token must echo | Accepted (not built) | Defence in depth for a shared machine | — |
| Unary responses are limited to `ClientConfig::maxResponseBytes` (16 MiB, aborted while downloading); destroying `ConnectClient` completes in-flight calls with `Cancelled`; an exception from a completion never leaves a Qt slot (`core::invokeGuarded`, also used by the OIDC completions) | Accepted (not built) | An unbounded body was buffered; calls vanished silently at teardown | A streaming RPC with large frames needs its own bound |
| Desktop CI runs clang-tidy a second time over the MSVC compile database for the Windows-only translation units (own baseline), with `concurrency-*` and `misc-*` enabled and naming/concurrency findings as errors | Accepted (UNVERIFIED: clang-cl mode on cl.exe commands and the LLVM `run-clang-tidy.py` path on `windows-latest`) | The Linux Clang database never compiles DPAPI/toast/dbghelp code | The first Windows run shows the approach needs different arguments or a different runner tool |
| Desktop OIDC stays a Core module (`Modules/Core/Oidc`, `Aedst::Oidc`) and is **not** moved into `Features/Auth` to mirror the other clients' auth feature layout. Honest reasons: (1) one `OidcSession` instance is a `network::TokenProvider` that `App/` hands to `ConnectClient` for EVERY feature's calls and that `App/` restores, refreshes and ends at startup and on `sessionExpired()` (`app_dependencies_session.cpp`), independent of whether the Auth screens are shown; inside `Features/Auth` it would be reachable by the other features and by Core code only through a feature, which `check-feature-boundaries.sh` forbids; (2) the GPL-or-commercial-only QtNetworkAuth dependency (ADR-0032 finding) is confined to this one target, so the open licence decision (buy Qt commercial vs. a Qt Network PKCE flow) is a single-module change. Not a technical impossibility: `Features/Auth` keeps only the `OidcAuthRepository` adapter and the login UI. Pointer for `docs/content/client-recipe.md`: "desktop sign-in = Core/Oidc (session, discovery, keychain) + Features/Auth/Data/oidc_auth_repository; do not look for the OIDC code in the auth feature" | Accepted (not built) | `apps/desktop/docs/adr/0025-oidc-authentication.md`, `apps/desktop/docs/adr/0032-licenses-compliance.md` | QtNetworkAuth is replaced or licensed and the session no longer has to be shared with the network layer, or the plugin architecture (ADR-0033) gains always-on core plugins that can own a token provider |

## Proposals awaiting the owner (nothing below is implemented; each has a recommendation)

| Question | Recommendation | Why it is not done | Detail |
|---|---|---|---|
| Unify the secret stores on QtKeychain and delete the DPAPI / libsecret / key-file master-key providers (about 820 lines) | **Yes**, after the first real build shows QtKeychain works on both OSes | Irreversible deletion of working-looking code that was never built or run; ADR-0003 names QtKeychain as its own revisit trigger | ADR-0003, "Proposal awaiting owner" |
| Velopack download: independent re-hash (the C++ SDK does not expose the package path) versus amending ADR-0029 / SECURITY.md to say the manifest's SHA-256 is bound to the feed and Velopack verifies the package itself | **Amend the documents** now (the claim in them is currently stronger than the code); revisit when the SDK exposes the path | A re-hash needs an SDK change or a path guess; the pipeline test for "empty download path = fail" would break the only installer | ADR-0029, "Proposal awaiting owner" |
| SQLCipher for the local database | **Not yet**: nothing but an already-encrypted session and the outbox payloads is stored; add it together with the first feature that stores user content offline | Needs a reviewed conversion plan and a new dependency | ADR-0028, "Proposal awaiting owner" |
| `google.rpc.ErrorInfo` through buf-generated messages instead of the hand-written wire-format parser in `connect_error.cpp` | **Yes**: parse the details with the generated `ErrorInfo` once the first build works | Touches the error model that every test replays; best done with a compiler | ADR-0026, "Proposal awaiting owner" |
