# Decisions: Android

Part of the [decisions index](/decisions). Status and verification legends are defined there.


| Decision | Status | Rationale | Revisit when |
|---|---|---|---|
| `security-crypto` / `EncryptedSharedPreferences` deprecated: Android Keystore + Tink AEAD (`AndroidKeysetManager`) with an encrypted DataStore serializer; legacy data migrated read, write, delete | Accepted | Upstream deprecation | Google ships a supported replacement |
| Latest-stable-only versions; Compose BOM via `platform()` | Accepted | Version policy | — |
| Hilt on AGP 9 with built-in Kotlin (no explicit `kotlin-android` plugin) kept; Metro only if KMP appears; Koin rejected (no compile-time checks) | Kept | Compile-time DI validation | KMP is adopted |
| connect-kotlin 0.9.0 over OkHttp 5.5.0 (compileSdk 37). **Plan B:** Wire / gRPC-Kotlin (server also serves gRPC and gRPC-Web) | Accepted | Same contract as other clients | connect-kotlin becomes unmaintained or blocks an AGP/Kotlin upgrade |
| JDK 21 required (project toolchain pin; AGP 9.4.1 / Gradle 9.8 baseline) | Accepted | The old reason (detekt 1.23 fails on JDK 25) is gone after the detekt 2 migration; JDK 25 with detekt 2 is UNVERIFIED, so the pin stays | JDK 25 verified green in CI (detekt 2, AGP) |
| `tv-foundation` deprecated: use standard Compose lazy lists on TV | Accepted | Upstream deprecation | — |
| Run `make generate` (buf) before the first build | Accepted | Generated stubs are not committed | — |
| Session lifecycle: OkHttp `Authenticator` refreshes once on 401 (single-flight, mutex); rejected refresh token clears the session; `SessionState` drives routing ([ADR-0013](/decisions/0013-android-offline-and-client-security)) | Accepted | An expired access token must not strand the user; one rotation per refresh token | Auth moves to an IdP SDK that owns refresh |
| Offline writes: Room outbox table + WorkManager delivery (`core/outbox`), at-least-once with the row id as `Idempotency-Key`; `NetworkMonitor` for UI | Accepted | Client mirror of the server outbox ([ADR-0011](/decisions/0011-outbox-relay-and-in-process-bus)); WorkManager already handles Doze, reboot and constraints | A feature needs read-side sync/conflict resolution (add it, keep the outbox for writes) |
| Room is not encrypted; only non-sensitive re-fetchable data goes in it; `allowBackup=false`; HTTPS-only `network_security_config`; TLS pinning from `-Paedst.certPins`, release build refuses to assemble without pins | Accepted | Secrets never belong in Room; a signed-in device state is not portable | Room must hold sensitive data (then SQLCipher or the encrypted store) |
| User-visible errors are localized by `AedstError` kind (`userMessageRes`), never the diagnostic message | Accepted | Raw server/transport text is English, leaky and untranslatable | — |
| Android tests: JVM Robolectric for Compose/Room/Worker (`testDebugUnitTest`), androidTest with Accessibility Test Framework checks on an emulator in CI | Accepted | UI and DB behaviour must be testable without a device on every PR | Robolectric lags a new compileSdk (then run those tests instrumented) |
| detekt **2.0.0-alpha.6** (`dev.detekt`) is the single pre-release exception to the stable-only version policy (explicit owner decision, 2026-10-08). 2.x is alpha-only on Maven Central; it embeds Kotlin 2.4.10 so it parses Kotlin 2.4 sources, which 1.23.8 (older compiler) could not. Renovate may propose newer `dev.detekt` pre-releases only (`ignoreUnstable: false` for that package). Formatting stays owned by ktlint, overlapping detekt rules disabled | Accepted | 1.23.8 cannot read Kotlin 2.4 language features reliably; the owner accepts alpha risk (config keys/rules may still change between alphas, config validation is on and fails loudly) for a working semantic gate | dev.detekt 2.0.0 stable (then drop the exception and the Renovate rule) |
| Firebase Crashlytics/Performance/Analytics replaced by Sentry Android + PostHog Android; Firebase kept only for FCM, google-services applied only when `google-services.json` exists | Accepted (not compiled) | Same telemetry split as Web/Apple; template builds without a Firebase project | — |
| Media: Media3 (ExoPlayer, Compose UI, Transformer), Coil 3, Photo Picker, WorkManager upload chain (prepare → presigned PUT → complete) | Accepted (not compiled) | Platform + AndroidX first | — |
| Renovate is the only dependency updater for Android too; `ben-manes.versions` + `version-catalog-update` removed; `task deps:update` bumps only the Gradle wrapper | Accepted | One tool for Go, pnpm and Gradle with PRs; two updaters on one catalog conflict | Renovate is replaced repo-wide |
| Navigation 3 (1.2.0) instead of Navigation Compose 2.x: app-owned back stacks of `@Serializable NavKey`, one stack per tab, sign-out resets every stack, `NavigationSuiteScaffold` shell; `sentry-android-navigation` replaced by a manual Sentry breadcrumb + PostHog screen | Accepted (not compiled) | New app: owning the back stack and adaptive layouts (tablet/foldable) natively; no migration cost | Nav3 API changes in a minor; list-detail scenes are a follow-up |
| Android sign-in = AppAuth-Android 0.11.1, Authorization Code + PKCE (S256) in a Custom Tab; first-party Login/RefreshToken RPCs no longer used by the app; `prompt=select_account`; sign-out revokes (RFC 7009) but does not end the IdP session | Accepted (not compiled) | ZITADEL is the IdP and first-party auth is off by default (the old password form could not sign in); WebView login is forbidden (RFC 8252) | A shared-device requirement (then `end_session` / `prompt=login`); App Links hardening |
| Android TV signs in with the OAuth Device Authorization Grant (RFC 8628, `DeviceAuthorizer` over the existing OkHttp, `slow_down` handled; user code on screen, no QR library); the TV client is a separate ZITADEL Native app with the Device Code grant (`bootstrap.sh`) | Accepted (not compiled) | TVs usually have no browser, so the AppAuth Custom Tab flow cannot run | ZITADEL stops offering the device grant, or a QR encoder is already a dependency |
| No `androidx.credentials` (Credential Manager) dependency: passkeys, MFA, social login and recovery run in the ZITADEL hosted login in the Custom Tab | Accepted | Native passkeys would require a custom login UI over the Session API (self-built identity, forbidden) and Digital Asset Links | A custom login UI over the ZITADEL Session API becomes a product requirement |
| JUnit 6.1.3 (Jupiter) is the test model in Android modules (about 33 test files migrated); `junit:junit` removed from the catalog and modules. The vintage engine stays **only** in modules whose Robolectric / Compose-rule / AndroidJUnitRunner tests have no Jupiter-native equivalent: `core/database`, `core/outbox`, `core/ui`, `core/ui-tv`, `core/security`, `feature/auth`, `feature/tasks`, `feature/media`, `benchmark`. **Supersedes** the earlier row "JUnit 4 stays in Android modules" | Accepted (not compiled) | Jupiter by default, vintage only where the JUnit 4 rule types are unavoidable; migration was done without a compiler | Robolectric / AndroidX test rules move to the JUnit Platform (then drop the vintage engine module by module) |
| Adaptive layouts via `androidx.compose.material3.adaptive` **1.3.0** (`currentWindowAdaptiveInfoV2`, `NavigableListDetailPaneScaffold` for tasks, width-constrained screens, hinge-safe). Navigation 3 list-detail scenes are **not adopted** | Accepted (not compiled) | Library-first: the official adaptive library instead of hand-written window-size code; Nav3 scenes are still moving | Nav3 list-detail scenes stabilise; Robolectric `@Config` window-size qualifiers prove brittle |
| Enum mappers are exhaustive; `TaskStatus.UNKNOWN` and `TaskPriority.UNKNOWN` added (UI shows an "unknown" label; the create screen hides it); no `else -> TODO` | Accepted (not compiled) | A new server enum value must not crash or be silently mislabelled in old clients | — |
| `core/ui` pruned by 21 components (Accordion, ExpandableSection, BottomNavigationBar, Breadcrumb, Carousel, Chart, CommandPalette, ContextMenu, DataTable, Drawer, LongPressPreview, Popover, OtpInput, Pagination, ScrollArea, SearchableDropdown, Slider, ToggleButton, ToggleGroup, Tooltip, AspectRatioBox); `AedstAlert` uses the success/warning palette tokens; `scripts/check-color-literals.sh` and `scripts/check-file-size.sh` run in `scripts/check-policies.sh` | Accepted (not compiled) | No unused kit code; no colour literals outside tokens | A screen needs a removed component (restore from git history) |
| Roborazzi 1.76.0 screenshot tests in core/ui (goldens recorded on Linux CI); ATF only instrumented (API 34+, unsupported on Robolectric) | Accepted (not compiled) | Visual and accessibility regressions in shared components (axe analogue) | Roborazzi/AGP 9 incompatibility |
| Android contract test: buf descriptor JSON vs generated connect-kotlin clients by reflection (`ProtoContractTest`); fails loudly when `AEDST_REQUIRE_CONTRACT` is set | Accepted (not compiled) | Server protos are the single source of truth, like the web mock-API contract test | — |
| R8 full mode + `isShrinkResources`; protobuf-lite keep rules in `core/network/consumer-rules.pro` because protobuf-javalite ships none; CI checks the rule reached R8 | Accepted | Release-only `Field ... not found` crashes | protobuf-javalite ships its own rules |
| kotlinx.serialization on Android: navigation keys and local JSON only, never API payloads; Firebase only for FCM; session replay off (single tool if ever enabled), all enforced by `scripts/check-policies.sh` | Accepted | Protobuf is the contract; double replay means double load and consent | Product asks for mobile session replay |
| Play Integrity: client uses standard requests; the server now decodes and judges them in `integrity` (`IntegrityService/VerifyIntegrityToken`, off by default via `AEDST_INTEGRITY_ENABLED`). **The Android app calls it best-effort once per sign-in (`SignInAttestation`, informational telemetry only: verified, reason, device verdict)**; nothing may block on it until enforcement is decided | Server implemented (fake-Google tests only; never called the real API), client wiring open | A token is only meaningful once the backend decodes it and checks `requestHash`; see [server ADR-0002](/server/modules#integrity) | Android calls `VerifyIntegrityToken` (needs `ProtoContractTest` descriptors/clients regenerated), or enforcement per RPC is decided |
| Library-First is machine-enforced on Android (2026-10-08): detekt `ForbiddenImport` instances (banned libraries, `Log`/`Dispatchers` only in `core/common`, `okhttp3` only in network modules, raw Material 3 widgets banned in features and apps), `GlobalCoroutineUsage`, `InjectDispatcher`, `SuspendFunSwallowedCancellation`, `ForbiddenMethodCall` for `Thread.sleep`; `detekt` depends on type-resolved `detektDebug`; compose-rules 0.6.7; Android Lint with `warningsAsErrors`; Kover floors; shell gates for serialization scope, catalog allowlist, UI tokens, screen previews, RPC contract and module boundaries. `scripts/test-gates.sh` is the negative self-test | Accepted | A rule without a failing test is a wish; type-resolved rules were silently skipped by the plain `detekt` task | A gate produces repeated false positives (tune it in `detekt.yml` with a written reason, do not delete it) |
| compose-rules 0.6.7 rules switched off with reasons (`detekt.yml`, `Compose:` block): `ParameterNaming` (rejects `onTabSelected`/`onDateSelected`, the Material names), `PreviewAnnotationNaming` (the multipreview is `@AedstWindowSizePreviews`), `UnnecessaryLaunchedEffect` (suggests an unkeyed `SideEffect`) | Accepted (owner may overrule) | The rules are opinionated; the three cost more churn than they protect | The owner wants present-tense lambda names in `core/ui`, or compose-rules makes `UnnecessaryLaunchedEffect` key-aware |
| `okhttp-coroutines` 5.5.0 (`executeAsync()`) replaces the hand-written `OkHttpAwait.kt` and `runInterruptible(Dispatchers.IO)`; okio `HashingSource` replaces the hand-written SHA-256 loop; Kotlin `ByteArray.toHexString()` replaces `"%02x".format` | Accepted | Library-First: platform and existing libraries before custom code | — |
| Screen / ViewModel / Repository / Module types in `feature/*` are `internal`; the public surface of a feature is its `*NavGraph` (and shell composables such as `NotificationsBadgedIcon`). `*Route` composables, use cases, `SignInAttestation`, `PushInitializer` and `AedstMessagingService` became `internal` with it | Accepted | A feature must not be reachable by another module except through navigation; enforced by `check-feature-boundaries.sh` | A feature needs a second consumer (then expose an API module, not its internals) |
| Lint findings fixed instead of baselined: `UseKtx`, `DataExtractionRules` (`data_extraction_rules.xml` excluding every domain in app and app-tv), user CAs only in `<debug-overrides>`, adaptive icon with monochrome layer, unused `common_*` strings removed. `GradleDependency`, `NewerVersionAvailable`, `AndroidGradlePluginVersion` are ignored in `lint.xml` because Renovate owns version bumps | Accepted | `warningsAsErrors` makes every warning a build failure | A baseline file becomes necessary (commit `lint-baseline.xml` per module, with an owner and a date) |
| Offline write path is real (2026-10-09 remediation): `feature/tasks` registers `task.create`, `task.complete` and `task.update` outbox handlers (payload = the request message in protobuf wire format, Base64 in the text column); `CreateTaskUseCase` / `CompleteTaskUseCase` are online-first and queue the **same operation id** they just sent as `Idempotency-Key` when offline (`NetworkMonitor`) or after a retryable failure. Every direct write (tasks create/complete/reopen/delete, `createUpload`) sends a fresh UUID `Idempotency-Key` per call, because `retryOnConnectionFailure(true)` re-sends a POST ([ADR-0013](/decisions/0013-android-offline-and-client-security)). Reopen and delete stay online-only; `task.update` has a handler but no producer (no edit screen yet) | Accepted (JVM-verified: MockWebServer header tests, Robolectric `OutboxSyncWorker` run through the real handlers) | The outbox existed but no feature used it; a lost response could apply a write twice | An edit screen is added (queue `task.update`), or a write needs ordering across entity types |
| Session end wipes user-bound local data through `SignOutHook.onSessionEnded` (explicit sign-out **and** a rejected refresh token): `OutboxSignOutHook` cancels the sync work and empties the outbox, `MediaSignOutHook` cancels uploads, deletes staged files and clears Coil's memory and disk caches, `UnreadCountSignOutHook` zeroes the badge. `beforeSignOut` (push unregister) is unchanged and still runs only while the session is valid | Accepted (JVM-verified; never run on a device) | Queued writes and cached thumbnails belong to the user who left; the next user must not send or see them | Pending writes must survive an involuntary sign-out (then key outbox rows by user id, as Apple's is planned to) |
| Parked (`FAILED`) outbox items are visible: an alert under the offline banner (`OutboxFailedAlert`) offers retry (requeue with a fresh attempt budget) or discard; failed items older than 30 days are deleted at the end of a drained sync run | Accepted | A write the server rejected used to disappear silently into a table nobody read | Product wants per-item review instead of all-or-nothing |
| Room schemas are committed, not ignored: `core/database/schemas/<db>/<version>.json` (the `**/schemas/` ignore was removed), `AppDatabase.VERSION` is the one version constant, `scripts/check-room-schemas.sh` (CI) fails when the file of the current version is missing, and `AppDatabaseSchemaTest` opens the exported schema as the real database (the identity hash catches a stale file). The `androidx.room` Gradle plugin 2.8.5 (`room { schemaDirectory }`) replaces the bare KSP argument, because the plugin declares the directory as a task input/output (with the build cache on, a cache hit would otherwise skip writing the JSON) | Accepted (JVM-verified) | Without the file a version bump has no migration source; the template's old `com.yourname.myapp` schemas were stale leftovers and were deleted | The Room plugin conflicts with a new AGP; then go back to the KSP argument and keep the check script |
| DataStore corruption recovers: `UserPreferencesSerializer.readFrom` turns `InvalidProtocolBufferException` into `CorruptionException` and `createUserPrefsDataStore` installs `ReplaceFileCorruptionHandler { defaults }`. Lost on a corrupt file: the analytics consent answer (asked again), onboarding flag and push bookkeeping (re-registered), all re-derivable. (The earlier test pinned the bug: a parse error was thrown at every reader.) | Accepted | A truncated write after a crash would otherwise break every read until the user cleared the app data | `UserPrefs` holds something that cannot be re-derived |
| `TinkEncryptedPreferences` fails closed: after `AndroidKeysetManager.build()` it requires `isUsingKeystore()`; if the keyset is not Keystore-protected the store refuses to read or write (no token is ever persisted in the clear) and the failure is reported as a non-fatal. With `minSdk 26` the Keystore is always used, so this is defence in depth against a silent fallback | Accepted (decision logic unit-tested; the Keystore itself is UNVERIFIED on a device) | A security fallback that nobody notices is worse than a visible failure | Tink changes the fallback semantics |
| Sign-in failures are diagnosable: `SignInDiagnostics` logs `error.message` at warn level and reports `Unknown`/`Storage` errors (bugs, not offline or denied) to the crash reporter as non-fatal, in both the browser and the device flow. The user still sees only the localized kind; analytics still get the kind only | Accepted | The AppAuth/IdP detail that explains a failed sign-in was thrown away | The message turns out to carry personal data (then log the kind only) |
| ViewModel contract (state data class + sealed intent via `onIntent` + sealed effect on a `Channel.BUFFERED` + `ErrorShown`, no mutable flow exposed, one `Job` per operation with `ensureActive()`, drafts and the search query in `SavedStateHandle`); see "ViewModel contract" in [android/architecture](/android/architecture). `NavigationTelemetry` is a `@Singleton` (it used to repeat the screen view after every activity recreate) | Accepted (JVM-verified; the Hilt + Navigation 3 `SavedStateHandle` path itself is UNVERIFIED on a device) | Overlapping loads let a slow older answer overwrite a newer one; screens differed in shape | A screen needs one-shot UI state that is not an effect (then add it to the contract, do not fork it) |
| Staged upload files have a lifecycle: `UploadStaging` owns `filesDir/media-uploads`; a terminal failure of any step, an app-initiated cancel (`MediaUploadScheduler.cancel`, sign-out; not a constraint stop, which retries), and a start-up sweep (`UploadStagingSweeper`, files no unfinished upload owns) all delete the copy. Local video stills are a Coil model (`LocalVideoThumbnail` + fetcher over `LocalThumbnailLoader`) instead of a hand-built loader in a composable | Accepted (JVM-verified) | Copies of the user's photos and videos were kept forever after a failed or cancelled upload | Uploads become resumable across process death by bytes (then keep the file until the server confirms) |
| Application modules share their build setup: `AndroidApplicationConventionPlugin` wires the release TLS-pin gate (`preReleaseBuild` -> `verifyReleaseCertPins`), `generateLocaleConfig`, LeakCanary 2.14 (debug only; latest stable on Maven Central, 3.0 is alpha) and `versionCode` for **both** `app` and `app-tv`; `app-tv` also applies the Sentry Gradle plugin (R8 mapping upload) and gets its buttons from `core:ui-tv` through `AuthNavGraph(actionButton)` | Accepted (release build with `-Paedst.allowUnpinnedRelease=true` verified on the JVM) | `app-tv` shipped an unpinned, un-symbolicated release; a TV screen used a phone button | A third application module (it gets all of this for free) |
| Android App Links: an `autoVerify` `ACTION_VIEW` filter for `https://${appLinkHost}/{tasks,media,notifications,search,admin}` (`-Paedst.appLinkHost`, placeholder default); the path goes through `AedstRoutes.linkForAppLink` -> `routeForLink` like a notification link. `app/assetlinks.json.example` is the file the web app must serve at `/.well-known/assetlinks.json` (not done here: web is out of scope). Navigating to a tab's root key resets that tab's stack; the bottom bar uses `switchTab` and keeps it | Accepted (unit-tested routing; link verification UNVERIFIED, needs a real domain and device) | Links shared from the web did not open the app; "go to the task list" landed on a stale detail screen | The domain is chosen (set `appLinkHost`, publish `assetlinks.json`, set the fingerprint) |
| The baseline profile has **not been recorded** (it needs a device or emulator); the README and build comment now say so, `scripts/check-baseline-profile.sh` warns in CI (`AEDST_REQUIRE_BASELINE_PROFILE=1` makes it fail once a profile is committed) and no startup numbers are claimed | Accepted | The docs claimed a committed profile that did not exist | First recording on a device |
| Gradle wrapper pinned by checksum: `distributionSha256Sum` for gradle-9.8.0-bin.zip, from services.gradle.org (verified 2026-10-09). **Dependency verification (`verification-metadata.xml`) is deliberately not enabled yet**: Renovate cannot regenerate it, so every dependency PR would fail until a human re-ran `--write-verification-metadata` (a very large file with AGP's tooling artifacts), and it must be generated and reviewed on a machine with network access to all repositories. Follow-up, not a rejection | Accepted (follow-up open) | Supply-chain integrity of the build tooling | Renovate (or CI) can regenerate and commit the metadata, or the dependency set stops moving weekly |
| Debug `BASE_URL` is a Gradle property with a loopback default: `-Paedst.debugBaseUrl` / `AEDST_DEBUG_BASE_URL`, default `http://10.0.2.2:8080/` (the host machine from the emulator, where `task dev` serves the API; the debug-only network security config allows exactly that cleartext host) instead of a hostname that does not exist | Accepted | A debug build could not reach any server out of the box | — |
| **Proposal (owner decision needed, not implemented):** replace the hand-written wire parsing of `google.rpc.ErrorInfo` in `core/network/ClientUpgrade.kt` (a `CodedInputStream` walk over the detail bytes) with the generated `google.rpc.ErrorInfo` message, by generating the `google.rpc` types through `buf` (the `buf.build/googleapis/googleapis` module as an extra input of the Android `buf.gen.yaml`; the server already writes the detail with the standard `errdetails.ErrorInfo`) and calling `ErrorInfo.parseFrom(detail.payload.toByteArray())`. Library-First says the generated type is the right tool; the cost is one more generated package in `kotlin-gen`, a `buf.yaml`/`buf.lock` entry and the lite-runtime check that it compiles next to the existing messages (UNVERIFIED) | Proposal | Hand-rolled parsing of a standard message is exactly what the one rule forbids; it was kept because the Connect detail API hands over raw bytes and no generated `ErrorInfo` was on the classpath | The owner approves the extra buf dependency (then also let `ErrorKindsReplayTest` read the reason through it) |
