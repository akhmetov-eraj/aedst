# Web Architecture

`apps/web` is the parity source of truth the three native clients
(`apps/android`, `apps/apple`, `apps/desktop`) are built to match — see
[architecture-android.md](/android/architecture), [architecture-apple.md](/apple/architecture),
and [architecture-desktop.md](/desktop/architecture), each of which documents
its own translation of this app's module/boundary shape. This doc covers
web's own stack and layout; read [architecture.md](/server/architecture) and
[modules.md](/server/modules) first for the backend concepts everything here maps
onto.

## Stack

- **Next.js 16** (App Router, Turbopack) + **React 19**.
- **ConnectRPC** via [Connect-ES](https://connectrpc.com/docs/web/getting-started)
  (`@connectrpc/connect`/`connect-web`/`connect-query`) — TypeScript client
  stubs generated by `buf` straight from `apps/server/api/proto`, no
  gateway of any kind in between; GraphQL was removed (see
  [ADR-0002](/decisions/0002-connectrpc)).
- **TanStack Query** for client-side caching around Connect calls.
- **next-intl** for i18n across five locales (`ar`, `en`, `ru`, `tj`, `uz`) —
  see [i18n.md](/i18n) for the per-module pattern every platform now follows.
- **shadcn/ui** (`src/shared/ui/`) — the UI-kit source of truth every native
  platform's design system is built to match; see [ui-kit.md](/ui-kit).
- React Hook Form + Zod, date-fns, dnd-kit, and the rest of the approved
  stack in [library-first.md](/library-first).
- Sentry, Vitest + Testing Library, Playwright.
- **Biome is the only linter/formatter** (no ESLint/Prettier); feature isolation is enforced by `apps/web/scripts/check-feature-boundaries.sh`; **knip** (`apps/web/knip.jsonc`) fails CI on unused dependencies/exports, its allowlist being the approved-not-yet-used libraries (adding to it requires a [library-first](/library-first) update).
- **No RxJS**: use TanStack Query, `AbortController`, async iterators, or Connect server streaming.
- Environment variables are parsed with Zod in `src/shared/env/{client,server}.ts`.
- The nonce-based CSP is built per request in `src/proxy.ts` only (not in `next.config.ts`); any new third-party origin must be added to it. Storybook 10 (devDependencies) documents every `src/shared/ui` component and fails on a11y violations.

## Project structure

```
src/
  app/                # Next.js App Router: routes, providers, i18n/sentry/seo config
    (pages)/[locale]/ # locale-prefixed route segments
    config/i18n/       # next-intl plumbing + common/ (app-shell) translations
    config/modules/    # the single module registry (registry.ts) built from the manifests
  modules/<id>/       # feature modules — manifest.ts + public.ts + UI + co-located i18n (auth, tasks, search, ...)
  shared/
    modules/          # the ModuleManifest contract (types only)
    api/connect/      # Connect-ES transport/client setup + generated stubs
    ui/               # shared UI components (shadcn-based) — see ui-kit.md
```

|---|---|---|
| `auth` | `auth` | complete worked example, including per-module i18n |
| `tasks` | `tasks` | reference module — the shape every native client's future `feature/tasks`/`Features/Tasks`/`Modules/Features/Tasks` follows |

## The boundary rule, translated

Server rule (ADR-0006): only a module's `api/` package may be imported
across module boundaries. Web's translation: a module under `src/modules/*`
never imports another module — cross-module navigation goes through Next.js
routes (`app/(pages)/[locale]/...`), the same route-based indirection
Android/Apple/Desktop use their own navigation abstractions for
(`AedstNavGraph`, `AedstRoute`/`Router`, `Aedst::Navigation`).

Each module has an explicit public surface, enforced by
`scripts/check-feature-boundaries.sh`:

- `modules/<id>/public.ts`: the components/loaders pages and the shell may use. Code outside the module (`src/app`, `e2e`) imports a module only through `@/modules/<id>/public`, `@/modules/<id>/manifest` or a single-export `@/modules/<id>/entries/<name>` (see below); `src/shared` imports no module at all.
- `modules/<id>/manifest.ts`: UI-free data (`ModuleManifest` in `src/shared/modules/manifest.ts`): `id`, `routes` (access, required role), `nav` entries, `i18nNamespaces`, `featureFlags`, `capabilities`, `permissions`. It may import only `@/shared/**`.
- `src/app/config/modules/registry.ts` is the one place that lists the modules. The route guard (`proxy.ts` via `route-guard.ts`), the primary navigation (`AppNav`) and the i18n loader (`i18n/modules.ts`) derive from it, so adding a module means a folder, a manifest and one registry line.
- Every `useFeatureFlag("x")` in a module must be listed in that module's manifest.
- Modules talk to each other only through the registry/manifests, `src/shared` (typed API clients in `shared/api`, shared query keys, URL state) or the server. A typed event contract goes in `src/shared` when the first real need appears (not built speculatively).

The architecture is prepared for, but does not adopt, microfrontends: see [Path to microfrontends](/web/microfrontends).

Each module owns its own `i18n/` catalog (`src/modules/<name>/i18n/*.json`)
rather than a single global translation file — this per-module rule is
mandatory across all five platforms now, see [i18n.md](/i18n).

Messages reach the browser per route, not all at once: the request config (`config/i18n/request.ts`) still loads every catalog for server components (`getTranslations`), but the root locale layout hands client components only `common` plus the namespaces of modules with a public route (`auth`, the sign-in landing). `(app)/layout.tsx` adds the shell widgets’ modules (`search`, `notifications`) and each module segment layout (`tasks`, `admin`) adds its own through `providers/RouteMessages.tsx`, which resolves a route path to namespaces from `manifest.routes` (`i18nNamespacesForRoutes`); `providers/ExtendMessages.tsx` merges the subset into the parent provider. A module without a route (`media`) is passed by name. Budgeted by `resource-summary:document:size` in `lighthouserc.json`; the subset sizes are asserted in `config/i18n/messages.test.ts`.

The signed-in shell layouts (and the notification pages) import `entries/<name>.ts`, not `public.ts`: a Server Component that imports
a barrel gets the client chunks of *every* component the barrel re-exports, so the signed-in
shell (which only needs the bell, the palette and the identity widgets) was shipping the
notification preferences, the admin tables and the sign-in form to every route (measured: -47 KB gzip first load on `/admin`, -16 KB on `/search`). Pages whose module is
not in the shell keep importing `public.ts`: per-page direct imports shrink first load a little
further but make Turbopack copy shared libraries (nuqs, base-ui) into every page chunk
(total emitted JS +50 KB). `public.ts` stays the full surface for tests, stories and e2e.

Outside code reaches a module only through `manifest.ts`, `public.ts` and `entries/*`, plus
`outbox.ts` (the client-safe entry for offline-outbox handlers: `public.ts`
also exports server-only prefetching sections that must not reach the browser
bundle). The outbox itself lives in `src/shared/lib/outbox`; see the decision
row in [decisions/web](/decisions/web).

## Routing and locales

Every page lives under a `[locale]` dynamic segment
(`app/(pages)/[locale]/...`); `next-intl`'s routing config
(`src/app/config/i18n/routing.ts`) drives locale detection/redirect and
`sitemap.ts` emits one entry per locale with `hreflang` alternates.

The locale root (`/[locale]`) is the sign-in landing page (app name, `AuthGate`, JSON-LD). An anonymous visitor stays there; a signed-in visitor never sees it, because `proxy.ts` redirects to the validated `?next=` or the tasks dashboard.

## Bundle and code splitting

One Next.js app, split per route: App Router/Turbopack emits a chunk graph per route, so a module's code ships only on its own routes. The signed-in shell (`(app)/layout.tsx`) is shared; heavy shell widgets load on demand (the command palette's cmdk dialog is a `next/dynamic` import that loads on first open). `pnpm check:bundle` reads `.next/diagnostics/route-bundle-stats.json` and enforces a first-load gzip budget per module (`modules.<id>.routePrefix`) and for shell routes in `bundle-budget.json`; a route with no owning budget fails the check. Build caching: Turbopack's on-disk cache (`.next/cache`) is what CI restores between runs; keep `.next/cache` in the CI cache key by lockfile hash.

## Auth, data and security model

The browser never holds a token and never talks to `apps/server`.

```
browser ──same-origin──▶ Next.js server ──API_BASE_URL──▶ apps/server
        cookies (httpOnly)   │
                             ├─ proxy.ts        nonce CSP · route guard · token refresh · next-intl
                             ├─ /api/auth/*     OIDC login (PKCE redirect) + callback → set cookies; logout Server Action
                             ├─ /api/rpc/*      BFF proxy: bearer from cookie, one refresh+retry on 401
                             └─ Server Components  prefetch → HydrationBoundary → client useQuery
```

- **Sign-in.** OpenID Connect Authorization Code + PKCE as a backend-for-frontend (`oauth4webapi`). `/api/auth/login` does discovery, generates state, nonce and a PKCE S256 verifier, seals them (AES-256-GCM, `OIDC_STATE_SECRET`) with the validated `next` into a 10-minute httpOnly pre-auth cookie and redirects to the IdP (`?screen_hint=register` adds `prompt=create`, ZITADEL's registration form). `/api/auth/callback` validates state, `iss`, the code exchange and the ID token (claims including nonce, plus its **signature** against the issuer's JWKS from discovery; asymmetric `RS256`/`ES256`/`EdDSA` only, `none` and HMAC refused; `oauth4webapi` caches the JWKS for 5 minutes and re-downloads it, at most once a minute, on an unknown `kid`), requires a JWT access token, writes the session cookies and clears the pre-auth cookie; any failure returns to `/?auth_error=<code>`. There are no password forms and the web app never calls `AuthService`.
- **Session.** Three httpOnly, SameSite=Lax cookies (`__Host-` prefixed over HTTPS): access token, refresh token and ID token (display identity and `id_token_hint`). `AuthProvider` only mirrors *who* is signed in (seeded by the server layout) and feeds Sentry's user context. Roles are read from the access token (`AUTH_ROLES_CLAIM`, e.g. ZITADEL's `urn:zitadel:iam:org:project:roles`; `AUTH_ROLES_ORG` optional) for rendering only.
- **Sign-out.** A Server Action (Origin-checked) clears the cookies, revokes the refresh token (RFC 7009, best effort) and returns the IdP's `end_session_endpoint` URL with `id_token_hint` and `post_logout_redirect_uri`, which the client navigates to; without an end_session endpoint only the local sign-out happens.
- **Refresh.** The OIDC `refresh_token` grant. `proxy.ts` rotates an expired access token before render (Server Components cannot set cookies); `/api/rpc` does the same for client requests. Refresh is single-flight per token in each process, and an ID token on a refresh response is signature-verified like the login one (a forged one ends the session). Across replicas the first `invalid_grant` for a token is treated as a lost rotation race: the request counts as signed out but the refresh cookie is left alone, and only the same token still refused 15 s later clears them; `invalid_token`/`unauthorized_client` clear immediately; an IdP outage never does. The client then shows a toast and redirects to `/?next=<where you were>`.
- **Route protection.** `proxy.ts` redirects anonymous visitors from `/[locale]/tasks/**` to `/[locale]?next=…` and signed-in visitors away from the login page. `next` is validated by `safeRedirectPath`.
- **CSRF.** The logout Server Action carries Next's Origin check; `/api/rpc` requires a same-origin `Origin`, rejects cross-site `Sec-Fetch-Site` and no longer proxies `AuthService` at all. The login flow is bound to the browser by the sealed state/PKCE cookie, so a forged callback is refused.
- **Server data.** `createRpcPrefetcher()` + `HydrationBoundary` (see `modules/tasks/ui/TasksSections.tsx`); sections stream independently through `<Suspense>`. Server and browser transports share a static query key so hydrated data is found.
- **URL state.** The task list's filters, sort, search and page cursors are nuqs parsers shared by server and client.
- **Errors.** Unauthenticated responses are handled globally in `QueryProvider`; other mutation errors toast (opt out per mutation with `meta: { silent: true }` when it renders its own error); unexpected errors go to Sentry with breadcrumbs. Trace headers flow browser → `/api/rpc` → apps/server.
- **Privacy.** Measurement (PostHog analytics + flags, Sentry Replay) is opt-in via the `aedst_consent` cookie. Session replay is Sentry-only; PostHog session recording is disabled.

## Virtual lists

A list that can grow past a few dozen rows is virtualized with TanStack Virtual (`useVirtualizer`). The reference is `modules/notifications/ui/NotificationsList.tsx` (used by `NotificationsInbox`):

- A scroll container with a bounded height (`maxHeight` and `overflowY` inline) wraps a `ul` whose height is `getTotalSize()`; each `li` is absolutely positioned with `translateY(row.start)` and measured with `ref={virtualizer.measureElement}` (rows vary in height). Positioning is inline style, not Tailwind classes, so it also works in component tests, where no stylesheet is loaded.
- Paging: `useInfiniteQuery` feeds the list and an empty sentinel after it (`shared/lib/hooks/use-sentinel.ts`, a native `IntersectionObserver`) calls `fetchNextPage`; an explicit "Load more" button stays as the non-scroll fallback.
- Accessibility: keep `ul`/`li` semantics, set `aria-posinset` and `aria-setsize` (`-1` while more pages exist) because rows are unmounted, keep rows as native buttons or links, and handle Arrow Up/Down, Home and End by `scrollToIndex` followed by focusing the mounted row.
- Tests run in real Chromium (Vitest Browser Mode), so layout exists and no element-size mocking is needed; assert that far fewer rows than items are mounted, the ARIA attributes, keyboard focus and that scrolling the container fetches the next page. `@tanstack/react-virtual` is listed in `optimizeDeps.include` of the browser project, otherwise Vite pre-bundles it late with a second copy of React.

## Media variants

Presets (ADR-0015): `thumb_64` tiny lists, `avatar_256` avatars and small square tiles,
`card_400` grids and cards (the only uncropped preset), `feed_800x600` feeds,
`story_1080x1350` stories. The server returns them as signed imgproxy URLs under
`VariantKind` 5-9 (plus a stored `POSTER` for video); the legacy kinds 1-3 are
`reserved` and gone.
`modules/media/thumbnail/variants.ts` selects by UI context (`pickAvatarUrl`,
`pickFeedUrl`, `pickStoryUrl`, `pickThumbnailUrl(media, size)`): the requested
preset, else the nearest preset the server returned, else the video poster, else
the original image. Presets crop differently, so they are never mixed in one
`srcset`. The full-size `ImageViewer` and video playback use the sanitized
original (`Media.url`) because presets are fixed boxes. Verified: `vitest` for
`src/modules/media` and `biome check` pass.
