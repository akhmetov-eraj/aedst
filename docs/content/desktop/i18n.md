# Desktop i18n

Cross-platform rules (locales, per-module ownership, content consistency) are in the [i18n overview](/i18n). This page covers only Desktop.

| | |
|---|---|
| Mechanism | Qt Linguist: `.ts` sources, CMake `qt_add_translations()` produces `.qm` |
| Module catalogs | `Modules/Features/<Name>/i18n/<name>_<locale>.ts` |
| In code | QML strings use `qsTr(...)`; C++ uses `QObject::tr(...)` or `QCoreApplication::translate(...)` |
| Why | Qt's own toolchain (`lupdate` / `lrelease`); no custom loader. |

## Status

| Module | Catalog |
|---|---|
| Common / app-shell | ✅ `App/i18n/app_<locale>.ts` (see App shell below) |
| Auth | ✅ `Modules/Features/Auth/i18n` (`LoginView` context, via `qsTr`) |
| App shell | `App/i18n/app_<locale>.ts`: `Main` (update banner, toolbar) and `UpgradeRequiredView` (forced-upgrade screen) contexts; partial catalog, grows with `lupdate` |
| Tasks | `Modules/Features/Tasks/i18n/tasks_<locale>.ts`: `TaskListView` context, the offline "pending sync" strings so far (the rest is filled by `lupdate`) |
| Admin, Media, Notifications, Search | ✅ `Modules/Features/<Name>/i18n/<name>_<locale>.ts` (en, ru, tg, uz, ar) |

See also [Desktop architecture](/desktop/architecture).
