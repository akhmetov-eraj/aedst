# Library-First: Apple stack

Part of the [Library-First standard](../library-first.md). Principles, version policy, explicit rejections and the Definition of Done are in [General rules](general.md).

> **Verification status:** `apps/apple` has not been compiled in any environment (development happens on Windows). The code and manifests have **only been statically reviewed**; the first build in Xcode is the acceptance test.

Swift, SwiftUI, Swift Concurrency (async/await, actors), Swift Testing (unit) and XCUITest (UI only). UI lives in `apps/apple/Core/AedstDesignSystem/`. **Minimum OS versions: iOS/iPadOS 18.0, macOS 15.0** (tvOS 18, watchOS 11, visionOS 2 for packages that list them). The single source is `apps/apple/Project.swift` (`iOSDeploymentTarget`, `macOSDeploymentTarget`); `platforms:` in every `Package.swift` must not exceed them. Reason: in October 2026 the current iOS is 26, the share of iOS 15/16 is small, and supporting them required workarounds (backporting Observation and navigation). There is no analytics audience to rely on (the app is not released); revisit based on real analytics. The floor can be lowered to iOS 17 / macOS 14 by changing one constant, and nothing needs to be brought back (Observation, `NavigationStack`, `performAccessibilityAudit` work from 17).

**Platform APIs instead of libraries**: `Observation`, `NavigationStack`, `AuthenticationServices`, `CryptoKit`, `DeviceCheck` (App Attest), `LocalAuthentication` (app lock), `Network`/`NWPathMonitor` (network reachability), `MetricKit` (diagnostics), `os.Logger`/`OSSignposter` (logs and profiling), `Security` (Keychain), `String(localized:)` + String Catalog (localization). There are no longer restrictions on `Duration` / `Task.sleep(for:)` and `Environment(_: Observable)` (`AedstClock` intentionally uses nanoseconds, while the protocol stays on `TimeInterval`).

**Sign-in (OIDC), details.** `OIDCAuthRepository`, `SignInMode` (`.password` | `.browser`), `SignInUseCase`; discovery and ID-token checks (`iss`, `aud`, `exp`, `nonce`; plus `azp`, `iat`, `at_hash` and **signature verification** (`OIDCJWS`/`OIDCKeySet`/`IDTokenVerifier`: JWKS from `jwks_uri`, 1 h cache, single-flight, one throttled refetch on an unknown `kid`, RS256/ES256/EdDSA allow-list, `none`/`HS*`/`crit` rejected; a missing `azp` with several audiences is tolerated because ZITADEL may omit it). Refresh is the `refresh_token` grant **without retries** (rotation and reuse detection): `invalid_grant` ends the session, other errors keep it; the refresh lifetime is estimated with `AEDST_OIDC_REFRESH_TTL_DAYS` (default 30). Sign-out = RFC 7009 revocation (best effort) + local cleanup (no `end_session`; `AEDST_OIDC_EPHEMERAL_SESSION` opts into a private browser session, see decisions/apple.md). A token response without `id_token` is refused. The redirect is the custom scheme `com.aedst.apple:/oauth2redirect` (an `.https` callback from iOS 17.4+ is a hardening follow-up and needs an AASA file). Off by default: an empty `AEDST_OIDC_ISSUER` keeps first-party email/password until `AEDST_AUTH_FIRST_PARTY_SUNSET`. Keys: `AEDST_OIDC_ISSUER`, `_CLIENT_ID`, `_SCOPES`, `_AUDIENCE_SCOPE`, `_REDIRECT_SCHEME`, `_REFRESH_TTL_DAYS`, `_WEBCREDENTIALS_DOMAIN` (Associated Domains `webcredentials:`, placeholder `idp.example.invalid`). **Passkeys** are provided by ZITADEL's hosted login inside the browser session; the app does **not** call `ASAuthorizationPlatformPublicKeyCredentialProvider` (that would be a custom identity feature); revisit if a fully native login UI is needed (ZITADEL Session API). Revisit AppAuth-iOS for DPoP/PAR/multiple IdPs. App settings in ZITADEL: Native app, authentication method None/PKCE, grants Authorization Code + Refresh Token, redirect URI exactly `com.aedst.apple:/oauth2redirect`, access token type JWT, role assertion, audience scope via `AEDST_OIDC_AUDIENCE_SCOPE`, `offline_access` allowed, passkeys enabled in the login policy.

**DI: swift-dependencies (Point-Free) was evaluated and is not accepted now.** The owner proposed it; checked 2026-10-08 (`git ls-remote` + raw `Package.swift`): the latest tag **1.17.1 declares swift-tools-version 6.4**, which Xcode 26.6 in CI cannot read (the same blocker that removed the swift-perception pin); 1.17.0 (tools 6.1) would require a version ceiling, another brittle constraint; constructor injection already gives compile-time verifiability without global state. Revisit when Xcode with Swift 6.4 becomes the CI default (then accept `@Dependency` for cross-cutting seams: clock, analytics, UUID/date) or when threading cross-cutting dependencies through layers becomes expensive; adopting it later is a local change.

**Transport, Plan B.** grpc-swift-2 (requires macOS 15 / iOS 18 / watchOS 11 / tvOS 18 / visionOS 2) **no longer runs into the OS floor**: the floor equals its minimum, so it is now a possible option. connect-swift remains the primary for the remaining reasons: a generated Connect client, owner decision.

**Release and CI.** The workflows `apple-beta.yml` / `apple-release.yml` use `ruby/setup-ruby` + `bundle exec fastlane` on `macos-26` with Xcode 26.6. The fastlane action parameters were checked against the fastlane 2.240.1 sources (match, gym, pilot, deliver, notarize, update_code_signing_settings); Ruby 3.4.11 is the last patch of the 3.4 branch (cache.ruby-lang.org, 2026-10-08). Signing via `update_code_signing_settings` overrides the xcconfig `CODE_SIGN_STYLE = Automatic` (settings in project.pbxproj take precedence over the target xcconfig), but it has **never been run**; the first real run is the acceptance test. `Gemfile.lock` is created on a Mac/Linux machine with `make gem-lock` and committed.

## Machine enforcement: one gate per mandatory library

Every "use X for concern Y" row above is a failing check, not advice. Nothing here has run under Xcode or SwiftLint
(not available in the authoring environment): the static mirror and the shell/Node gates run anywhere and were run
on the real tree plus negative fixtures; the SwiftLint engine itself is **UNVERIFIED** until the first macOS CI run.

| Concern -> mandatory tool | Gate (source of truth) | Static / CI command | Negative self-test (must fail) |
|---|---|---|---|
| State: Observation, not `ObservableObject`/`@StateObject`/`@ObservedObject`/`@EnvironmentObject` | `no_observable_object` in `.swiftlint.yml` | `scripts/check-swiftlint-rules-static.sh` | `scripts/fixtures/swiftlint/bad/**` |
| Reactive/persistence: async/await + GRDB, not Combine/SwiftData/CoreData | `no_combine_swiftdata` | same | same |
| Telemetry SDKs only in `Core/AedstTelemetry` (Sentry, PostHog); Nuke only in `Core/AedstMedia`; GRDB only in `Core/AedstPersistence`; Connect only in `Core/AedstNetwork`, `App/Shared`, `Features/*/Data` | `sdk_telemetry_only_in_telemetry`, `sdk_nuke_only_in_media`, `sdk_grdb_only_in_persistence`, `sdk_connect_only_in_network` | same | same |
| Generated proto types (`Aedst_*_V1_*`) only in `Features/*/Data` and `Core/AedstNetwork` | `generated_types_only_in_data` | same | same |
| Settings: GRDB / Keychain, never `UserDefaults` | `no_user_defaults` | same | same |
| Logging: `AedstLogger`, never `print`/`debugPrint` | `no_print` | same | same |
| Remote images: `AedstRemoteImage`/`AedstAvatar` (Nuke), never `AsyncImage` | `no_async_image` | same | same |
| Concurrency: no `Task.detached` without a same-line `// concurrency-ok: reason`; no `Task.sleep(nanoseconds:)` (use `.seconds` or `AedstClock`) | `no_task_detached`, `no_sleep_nanoseconds` | same | same |
| Time: `AedstClock` injected, no `Date()`/`Date.now` in `Presentation/` and `App/` | `no_wall_clock_in_presentation` | same | same |

| Localization: integer placeholders need `variations.plural`; `String(format: String(localized:))` banned (use `String(localized: "key \(value)")`, catalog key `key %lld`) | `apps/apple/scripts/i18n-apple-checks.mjs` | `node scripts/check-i18n-parity.mjs` (`task check:i18n`) | `node apps/apple/scripts/i18n-apple-checks.mjs --self-test` |

The `custom_rules` block in `apps/apple/.swiftlint.yml` is the **single source**: SwiftLint (CI, `--strict`) and
`apps/apple/scripts/swiftlint-rules-static.mjs` (parses that same block: same regex, `included`, `excluded`; comments never
match) cannot drift. `scripts/check-feature-boundaries.sh` (CI step, `make check`) runs all of the above; `make lint` runs them
before SwiftLint. Fixtures use the extension `.swift.fixture` / `Package.swift.fixture` so no real tool picks them up.
