# Release build: R8 full mode and keep rules

`:app` and `:app-tv` release builds run **R8 in full mode** (the AGP default since 8.0, no opt-in property) with
`isMinifyEnabled = true` and `isShrinkResources = true`, set once in the `aedst.android.application` convention plugin.
Full mode removes and renames anything not provably used, so reflection must be covered by keep rules. The debug build
does not minify, so an R8 problem only shows in release - that is why CI assembles it (`android-ci.yml`,
"Assemble release (R8)") and why the checklist below exists.

## Where rules live

| Source | Owns |
|---|---|
| Library consumer rules (inside the AAR/JAR) | Hilt/Dagger, Room, WorkManager, OkHttp, Tink (own embedded protobuf), Sentry, PostHog, Firebase, connect-kotlin (Moshi adapters for its JSON error payloads), kotlinx.serialization (`META-INF/com.android.tools/r8`) |
| `core/network/consumer-rules.pro` | **protobuf-lite** keep rules (see below). Applies to every app that includes the module, including `core/datastore`'s `UserPrefs` |
| `app/proguard-rules.pro`, `app-tv/proguard-rules.pro` | application-only rules (source file attribute for Sentry de-obfuscation) |

Library modules ship `consumer-rules.pro` (wired by `aedst.android.library` when the file exists); the app files stay
small. A rule belongs to the module that owns the reflective access, never copy-pasted into the app.

## protobuf-lite: the usual source of release-only crashes

`protobuf-javalite` 4.36.x ships **no** R8/ProGuard rules (checked on the 4.36.2 jar). A `GeneratedMessageLite` builds
its schema from a descriptor string and reads/writes the message fields **by name through reflection**. If R8 renames
or drops a field, the crash appears only in the minified build:

```
RuntimeException: Field bitField0_ for com.aedst.tasks.v1.Task not found
```

The rule in `core/network/consumer-rules.pro`:

```
-keepclassmembers class * extends com.google.protobuf.GeneratedMessageLite { <fields>; }
```

keeps every generated message field (including `bitField0_`, oneof case/value fields). Companion rules keep
`getDefaultInstance()` / `parser()` (used by connect-kotlin's `GoogleLiteProtoAdapter`) and the enum `forNumber(int)`
lookup. They are deliberately narrower than `-keep class ** extends GeneratedMessageLite { *; }`, which would block
shrinking of all generated code.

## kotlinx.serialization

Allowed only for type-safe navigation keys and small local JSON (never API payloads - the API is protobuf, see
[Library-First](/library-first#android)). `kotlinx-serialization-core` ships its own R8 rules; no app rule is needed
for `@Serializable` classes.

## Verifying a release build

1. `./gradlew :app:assembleRelease -Paedst.allowUnpinnedRelease=true` (CI does this; real TLS pins are injected by the
   release pipeline).
2. Inspect `app/build/outputs/mapping/release/`: `mapping.txt` (uploaded to Sentry when `SENTRY_AUTH_TOKEN` is set),
   `configuration.txt` (the merged rule set - it must contain the `GeneratedMessageLite` rule), `usage.txt`.
3. Smoke on a device or emulator with the **release** (or `benchmarkRelease`) variant: sign in, open the task list,
   open a detail (protobuf decode), toggle analytics consent (Proto DataStore), background and resume. Any
   `Field ... not found`, `ClassNotFoundException` or `NoSuchMethodException` points at a missing keep rule.
4. Never silence R8 with a blanket `-dontwarn` or `-keep class com.aedst.** { *; }`; add the narrowest rule to the
   module that owns the reflection.
